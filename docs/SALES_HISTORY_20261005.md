# Refresh and sales-history foundation (5 October 2026)

UI-REFRESH-01: opening a draft fetches its latest server JSON with no-store and a timestamp. Failed or out-of-order requests never silently show an old sheet. A compact refresh control reloads Drafts. Old restored backups migrate the structured description layout; the printed tag can be recovered only from explicit saved Size keywords and a validated tailoring conversion.

PRICE-05 / PRICE-06: SQLite sales.db records seller-confirmed listed/sold/withdrawn/returned lifecycle state, first published date, actual accepted price excluding postage, platform, sale date, buy/selling costs, days to sell and the full structured item snapshot including keywords, brand, cloth maker/line, material, size, colour and condition. A physical item has one outcome row; corrections replace that row without double-counting. Returned sales are excluded from pricing and revenue. A previous transaction remains stored for a returned item. No buyer names/details are collected. The hosted app remains a single private operator; cross-user pooling and account isolation are not implemented.

Confirmed sales survive deleting draft photos and are included in complete export/import backups. Device IndexedDB keeps a separate history record so deleting a draft backup cannot delete sales history. Restores add missing records only; current server corrections win. The free server still requires device/export backups; shared durable storage is not provisioned.

Pricing uses an indexed deterministic signature: brand, garment group, gender, condition, model/sub-brand, cloth maker/line, premium fibre/construction/grades, cut and pattern must match. Size/colour can vary. Platforms stay separate. At least 3 confirmed sales from the past 365 days are needed for a median suggestion. New Vinted generations/reprice use that median instead of generic estimates; opening a saved draft does not change its asking price. Mean/range/sample count are retained. These are this seller's observed accepted prices, not a guaranteed market valuation.

30-day sell-through: denominator is tracked items first published 30–120 days ago, numerator is those sold within 30 days of publication. Unsold/withdrawn inventory remains in the denominator; unknown dates are excluded. Profit is calculated only when both purchase cost and selling costs are known, with explicit zero supported. Recording unsold inventory matters; entering only sales creates a biased cohort. CSV export is optional; SQLite is the database.

JEV assessment: the existing JEV_ROUTING.md recommends deterministic parsing/calculation/database lookup first. No Jev SDK/credentials are present in this repository. Future optional shadow testing can rank ambiguous semantic candidates from an indexed short list with no-match/manual-review options, cached feature hashes, bounded typed questions and human-labelled evaluation. Never use Jev to invent prices or missing materials, and compare complete pipeline accuracy/cost before enabling it. This implementation makes zero model/Jev calls.

Verification: 865 Python tests passed, including API recording, price learning, platform/premium exclusion, correction deduplication, returns, dates, maturity cohorts, profit unknowns, migration and backup restoration after deleting photos. Node tests cover fresh sheet loading, race/error handling, archive/tombstone/sales recovery and camera/gallery. Drafts/Stats templates render and their JS syntax checks pass. Deployment and real phone interaction are separate checks; no fake sales added to live history.
